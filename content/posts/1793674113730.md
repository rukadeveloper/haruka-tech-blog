<img src="/media/images/uploads/1793673856127.png" width="588" data-align="left" style="display: block; height: auto; max-width: 100%; margin: 0px auto 0px 0px;"><h3><strong>클로드 코드 초기 셋팅</strong></h3><p>클로드 코드 설치는 <a target="_blank" rel="noopener noreferrer nofollow" href="https://code.claude.com/docs/ko/quickstart">https://code.claude.com/docs/ko/quickstart</a> 를 참고해주세요.</p><p>먼저 Claude Code를 시작할 때 주의할 점은 프로젝트 루트 디렉토리에서 Claude Code를 시작하는 것입니다.</p><p>그 이유는 Claude가 현재 디렉토리 기준으로 파일을 탐색하기 때문입니다.</p><h3>/init</h3><p>/init를 통해 CLAUDE.md 파일을 생성합니다. </p><p>CLAUDE.md 파일이 왜 중요하냐면 이 프로젝트의 모든 컨텍스트를 담고 있는 하나의 파일이기 때문입니다.</p><p>Claude가 작동하는 원리를 알아보자면</p><p>Claude는 모든 파일을 읽어올 수 있고, 그 파일을 읽어오고 나서 그것을 바탕으로 어떤 태스크를 수행합니다.</p><p>그 과정에서 프로젝트가 크면 클수록 모든 것을 읽어와야 하므로 토큰 소모량이 아주 큽니다.</p><p>그래서 매번 파일을 읽어오는 비효율적인 방법보다는 CLAUDE.md 라는 파일에 프로젝트의 구조를 정리를 하고</p><p>Claude가 이 파일만 읽고 바로 태스크를 실행할 수 있게 효율적으로 만들어주는 역할을 합니다.</p><p><a target="_blank" rel="noopener noreferrer nofollow" href="http://CLAUDE.md">CLAUDE.md</a> 에 다음과 같은 정보가 들어갈 수 있습니다.</p><ul><li><p>프로젝트명</p></li><li><p>절대 규칙 (Critical Rules)</p></li><li><p>아키텍처 (Architecture) - 트리 형식으로 제공합니다.</p></li><li><p>기술 스택 (Tech Stack)</p></li><li><p>빌드 &amp; 테스트 명령어 (Build &amp; Test Command)</p></li><li><p>도메인 컨텍스트 (Domain Context) - 비즈니스 로직 (상품들, 색상/사이즈, 재고보유 등...)</p></li><li><p>코딩 컨벤션 (Coding Conventions)</p></li><li><p>핵심 패턴 (Core Pattern)</p></li></ul><p>다만, CLAUDE.md 가 커지면 커질수록 토큰 소모량이 커지므로, 300자 이내로 유지하는 것이 일종의 원칙입니다.</p><p>만약 CLAUDE.md 파일이 커진다면 폴더 별로 CLAUDE.md 를 나눠서 작성하는 것이 옳겠습니다.</p><p>CLAUDE.md는 우리가 수정할 필요 없이 프로젝트가 끝나면 프롬프트로 추가해달라고 명령만 해주면 됩니다.</p><p>그리고, CLAUDE.md에는 Trigger Keywords 라는 것을 등록할 수 있는데요.</p><p>예를 들어 다음과 같은 프롬프트를 작성합니다.</p><blockquote><p>CLAUDE.md에 트리거 키워드 설정하되, 테스트 패스한다는 가정하에 git commit, push 한번에 해줘.</p></blockquote><p>CLAUDE.md가 설정한 키워드가 감지되면 요청한 단계를 통해 태스크가 이루어집니다.</p><h3>Compound Engineering</h3><p>팀 전체가 같은 규칙으로 Claude를 사용하는 것입니다. 하지만, 로컬 전용 경로나 개인 API 키 같은 것은 빼줘야 합니다.</p><p>이 글로벌 CLAUDE.md를 팀이 관리를 하면서 계속 코딩 컨벤션이나 아키텍처 등을 업데이트 하면</p><p>1명의 팀원이 아키텍처 업데이트를 했더라도, 똑같은 프로젝트에서 pull을 했을 때 효율적으로 Claude를 활용합니다.</p><h3>핵심 단축키</h3><ul><li><p>Shift + Tab  -&gt; Plan Mode와 Accept Mode 전환</p></li></ul><ol><li><p> <strong>Accept Edits on </strong>: 바로 Claude가 파일을 변경할 수 있는 write 권한이 생깁니다.</p></li><li><p><strong> Plan Mode : </strong>말 그대로 계획만 짜는 Mode, write 권한이 없습니다.</p></li><li><p> <strong>Plan Mode를 사용하는 실무적 이유</strong></p><p>토큰 최적화를 하기 위함이며, 불필요한 코드 생성을 방지하고, Plan Mode에서 방향을 먼저 확인하면</p><p>잘못된 코드 생성 &gt; 수정 요청 &gt; 재생성의 악순환을 끊을 수 있고</p><p>Claude Code는 대화가 길어질 수록 이전 컨텍스트를 압축하거나 날리게 되는데</p><p>Plan Mode로 짧은 텍스트 계획을 먼저 세우면, 실제 코딩 단계에서 컨텍스트 윈도우를 코드 생성에 온전히 씁니다</p></li></ol><p> </p><p>  </p><p></p><p></p><p></p>
