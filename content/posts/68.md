**동적 라우팅 - 상세 페이지 찍어내기**

단 하나의 파일만으로 무한대의 페이지를 생성하는 것이 동적 라우팅(Dynamic Routes)입니다.

게시판의 글 번호, 사용자의 ID, 상품의 고유 코드 등은 미리 예측할 수 없는 가변적인 데이터입니다.

이 때, Next.js는 \[\]라는 마법의 문법을 제안합니다.

![](/images/posts/68/2.png)

폴더에 \[\](대괄호)를 씌우는 순간, 그 폴더는 더 이상 고정된 이름이 아니라

어떤 값이든 받아들이는 와일드카드로 변신하게 됩니다.

백문이 불여일견, 예시로 어떻게 해석되는지 살펴보겠습니다.

우선 app/ 폴더 안에 products/ 라는 폴더를 만듭니다.

![](/images/posts/68/3.png)

그 안에 **\[slug\]** 이름이라는 폴더를 생성해보세요.

![](/images/posts/68/4.png)

\[\] 안에 들어가는 slug는 변수의 이름입니다. 

slug는 보통 URL에서 사람이 읽기 편하기 표현된 텍스트를 뜻합니다.

이렇게 설정한다면 SEO 추적에도 유리합니다.

이제 이 slug 값을 받아올텐데, Next.js 15+ 부터 바뀐 점이 있습니다.

URL의 정보를 담는 params가 일반 객체가 아니라 Promise 객체로 변경되었다는 사실입니다.

코드로 확인해봅시다.

```javascript
export default async function ProductDetailPage({ params }: { params: Promise<{ slug: string }> }) {
    const { slug } = await params

    return (
        <div className="p-18">
            <h1 className="text-4xl font-bold text-blue-600">상품 상세 페이지</h1>
            <p className="text-xl mt-4 text-gray-700">
                고객이 요청하신 상품의 코드는 다음과 같습니다.
                <span className="font-bold text-red-500 ml-2 text-3xl">{slug}</span>
            </p>
        </div>
    )
}
```

여기서 slug가 포함된게 Promise 객체이므로, 함수를 async 함수를 만들고 await 키워드를 통해 꺼내옵니다.

브라우저에서 다음과 같이 테스트해봅시다.

![](/images/posts/68/5.png)

결과로는 다음과 같이 맵핑됩니다.

![](/images/posts/68/6.png)

이로써, URL에 입력된 값을 가지고, 데이터베이스에게 해당 slug를 가진 상품을 찾아달라고

명령만 내리면 되는 것입니다. URL 자체가 데이터를 조회하는 queryKey가 되어버립니다.

이를 조금 더 응용해보도록 하겠습니다.

마지막으로, 주의해야 할 점은 동적 라우팅은 강력하지만, 우선순위라는 규칙이 존재합니다.

여기서 사용자가 **/..../products/new** 라고 접속했을 때, 목적지는 어디가 될까요?

정답은 구체적인 것이 우선하므로, 정적 페이지를 보여줍니다. 따라서 이름이 겹칠 걱정은 하지 않아도 됩니다.

**동적 라우팅 - 실전 쇼핑몰 상세페이지 구축**

실제로, 웹 사이트에서 위에서 말한 동적 라우팅을 직접 입력해서 들어가는 경우는 없습니다.

따라서, 상품 목록을 보여주는 리스트 페이지를 만들고, 클릭으로 동적 상세 페이지로 이동하는 흐름을 구성해야 합니다.

실습을 위해 임시 데이터(Mock Data)를 구성해야 하며, 그전에 먼저 app/ 안에 shop-products/ 안에 page.tsx를 만듭니다.

**Search Params**

평소에 쇼핑몰을 이용하던 경험을 떠올려보면, 내가 원하는 브랜드 상품을 검색해서 찾아봅니다.

이 때, 웹 브라우저의 주소창에 ?와 함께 붙는 꼬리표를 유심히 보면 다음과 같습니다.

![](/images/posts/68/15.png)

이것을 정식 명칭으로 **Search Params** 혹은 **Query String** 이라고 부릅니다.

여기서 개념부터 정리해보겠습니다.

지난 번에 배운 **\[slug\] 주소창**이 목적지라면, **Search Params**는 구체적 옵션과 같습니다.

Next.js에서는 서버 컴포넌트에서 props.searchParams가 전달됩니다.

그리고 15+ 버전에서 꺼내는 방식이 달라졌습니다.

예전 버젼에서는 동기 방식으로 바로 꺼낼 수 있었지만, 15+ 부터는 비동기 방식으로 기다려야 합니다.

이렇게 바뀐 이유는 **성능**과 **랜더링 효율성** 때문인데

**성능 측면**에서 이전 방식에서는 props.searchParams를 전달할 때까지 작업을 멍하니 기다렸습니다.

그러나 변경된 방식에서는 세부 옵션 요청을 고민하는 동안 다른 작업을 진행할 수 있게 되었습니다.

**사용자 경험 측면**에서는 데이터를 즉시 열어보는 방식은 데이터 처리가 끝날 때까지 화면이 멈추었습니다. (블로킹)

하지만, 비동기를 사용할 경우, 데이터를 기다리는 동안 뼈대(Skeleton)을 먼저 전송하는 스트리밍 방식입니다.

이제 직접 코드를 통해서 살펴봅니다.

다음과 같이 먼저 src/ 안의 app/ 안에 sort-products/를 만들어 **page.tsx**를 만듭니다.

그리고 상품의 정보를 배열 정보로 가짜 데이터로 만듭니다.

```javascript
const products = [
  { id: 1, name: '초경량 노트북', price: 1200000 },
  { id: 2, name: '무소음 기계식 키보드', price:185000 },
  { id: 3, name: '인체공학 버티컬 마우스', price: 89000 }
]
```

그리고 PageProps 인터페이스를 정의합니다.

```javascript
interface PageProps {
  searchParams: Promise<{ sort?: string }>
}
```

다음으로 컴포넌트 함수를 작성합니다.

```javascript
export default async function ProductListPage({ searchParams }: PageProps) {
    const { sort } = await searchParams

    const sortedProducts = [...products].sort((a, b) => {
        if (sort === 'asc') {
            return a.price - b.price
        } else if (sort === 'desc') {
            return b.price - a.price
        } else {
            return 0
        }
    })

    return (
        <div className="p-10">
            <div className="flex justify-between items-center mb-8">
                <div className="space-x-2 text-black">
                    <Link
                        href="/search-products?sort=asc"
                        className="px-3 py-12 bg-gray-200 rounded text-sm"
                    >
                        가격 낮은 순
                    </Link>
                    <Link
                        href="/search-products?sort=desc"
                        className="px-3 py-12 bg-gray-200 rounded text-sm"
                    >
                        가격 높은 순
                    </Link>
                </div>
                <div className="grid gird-cols-1 gap-6">
                    {sortedProducts.map((product) => (
                        <div
                            key={product.id}
                            className="border rounded-lg p-6 shadow-sm"
                        >
                            <h2 className="text-xl font-bold mb-2">{product.name}</h2>
                            <p className="text-gray-600 text-white mb-4">
                                {product.price.toLocaleString()}원
                            </p>

                            <Link
                                href={`/search-products/${product.id}`}
                                className="inline-block bg-blue-600 text-white px-4 py-2"
                            >
                                상세보기
                            </Link>
                        </div>
                    ))}
                </div>
            </div>
        </div>
    )
}
```

여기서 이해해야 할 점은 URL이 바뀌면, 서버 컴포넌트가 다시 실행된다는 점입니다.

버튼을 눌러서 주소를 바꾸는 순간, 주소창에 sort라는 값이 바뀌었음을 감지합니다.

그리고 서버 컴포넌트 함수를 처음부터 다시 실행합니다.

그때 비로소, await searchParams 함수가 다시 실행되면서 새로운 sort 값을 가져오고 

그에 맞춰 정렬 순서가 바뀐 새로운 HTML을 만들어서 우리에게 보여주는 것입니다.

![](/images/posts/68/16.png)

이제 응용된 방식으로, Next.js의 서버 컴포넌트를 이용해 <form>만으로 완벽한 검색 기능을 구현해봅시다.

복잡한 Javascript 로직 없이 웹의 본질적인 기능만으로 작동하는 서버 사이드 검색창을 만듭니다.

여기서 Javascript 로직은 React에서 주로 사용하는 useState 상태 관리나

이벤트 핸들러 같은 클라이언트 기반 Javascript 로직 없이 구현함을 의미할 것입니다.

브라우저가 이미 알고 있는 기본 규칙을 활용하여, 웹의 본질적인 기능만으로 서버 사이드 검색창을 만들 것입니다.

이를 위해 **웹 플랫폼 퍼스트 철학**에 대해 짚고 넘어가야 합니다.

우리들이 웹 상에서 입력이나 클릭 같은 행동을 하면, 브라우저는 어떻게 반응할까요?

HTML 표준에 따르면, <form> 태그 안에 있는 입력값들은 전송되는 순간

자동으로 URL의 Query String으로 변환됩니다.

예를 들어 다음과 같은 코드로 가정해봅시다.

```javascript
<form action="/shop-products" method="GET">
  <label for="search-input">상품 검색 : </label>
  <input 
    id="search-input"
    type="text"
    name="q"
    placeholder="검색어를 입력하세요"
    required
  />
  <button type="submit">검색</button>
</form>
```

여기서 <form> 태그 안의 action URL과 <input> 태그 안의 name 속성을 주의깊게 봐 주세요.

사용자가 **notebook** 입력하고, 전송을 누르면 브라우저는 **/shop-products?q=notebook** 으로 요청을 보냅니다.

우리가 굳이 Javascript로 URL을 조작하거나, 라우터를 호출하지 않아도 HTML 자체가 URL 구조를 만들어줍니다.

Next.js는 이러한 웹의 기본 동작 위에서 작동하기 때문에 Javascript가 로딩되지 않은 환경에서도

이 검색 기능은 즉시 작동합니다.

![](/images/posts/68/17.png)

이제 이 내장 기능을 그대로 이용하여 코드를 작성해보겠습니다.

먼저, **components**/ 폴더를 만들고, **Search.tsx** 파일을 만듭니다.

```javascript
export default function Search({ initialQuery }: { initialQuery: string }) {
    return (
        <form action="/shop-products" className="flex flex-1 flex-shrink-0 relative">
            <label htmlFor="search" className="sr-only">Search</label>
            <input
                name="q"
                className="peer block w-full border border-gray-200 py-[9px] pl-10"
                placeholder="검색어를 입력하세요"
                defaultValue={initialQuery}
            />
            <button type="submit">검색</button>
        </form>
    )
}
```

여기서 defaultValue는 서버에서 받아온 초기값인 initialQuery를 넣어주어, 검색어가 유지되게 합니다.

이것이 비제어 컴포넌트의 핵심입니다. 복잡한 상태를 React가 일일히 통제하지 않고 브라우저가 관리하도록 두는 것입니다.

이렇게 하면 서버 사이드 랜더링(SSR) 시점에 서버가 미리 URL에 있는 검색어를 input 창에 채워서 보내줍니다.

따라서, 페이지 이동 후에도 검색창에는 값이 그대로 유지되는 UX를 경험할 수 있습니다.

이것이 웹 표준의 힘입니다.

이제 방금 만든 검색 창을 상품 목록 페이지(/shop-products)에 넣어봅니다.

```javascript
import Link from "next/link"
import Search from '@/components/Search'

const products = [
    { id: 1, name: '초경량 노트북', price: 120000 },
    { id: 2, name: '무소용 기계식 키보드', price: 185000 },
    { id: 3, name: '인체공학 버티컬 마우스', price: 89000 }
]

interface PageProps {
    searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}

export default async function ShopProductListPage({ searchParams }: PageProps) {
    const params = await searchParams

    const query = typeof params.q === 'string' ? params.q : ""
    const sortOrder = typeof params.sort === 'string' ? params.sort : ""

    let filteredProducts = [...products]

    if (query) {
        filteredProducts = filteredProducts.filter(products => products.name.includes(query))
    }

    if (sortOrder === 'asc') {
        filteredProducts.sort((a, b) => a.price - b.price)
    } else if (sortOrder === 'desc') {
        filteredProducts.sort((a, b) => b.price - a.price)
    }

    return (
        <div className="p-10">
            <h1 className="text-3xl font-bold mb-8">이달의 추천 상품</h1>
            <div className="grid grid-cols-1 md:grid-cols-3 gap-6">
                <div className="w-full">
                    <Search initialQuery={query} />
                </div>
                <div className="flex gap-2">
                    <Link
                        href={{ query: { q: query, sort: 'asc' } }}
                        className="px-3 py-2 bg-white text-sm"
                    >
                        가격 낮은 순
                    </Link>
                    <Link
                        href={{ query: { q: query, sort: 'desc' } }}
                        className="px-3 py-2 bg-white text-sm"
                    >
                        가격 높은 순
                    </Link>
                </div>

                {filteredProducts.map((product) => (
                    <div key={product.id}
                        className="border p-6 shadow-sm">
                        <h2 className="text-xl font-bold mb-2">{product.name}</h2>
                        <p className="text-white-600 mb-4">
                          {product.price.toLocaleString()}원
                        </p>
                        <Link
                            href={`/shop-products/${product.id}`}
                            className="inline-block px-4 py-2 rounded hover:bg-blue-700">
                            상세보기
                        </Link>
                    </div>
                ))}
            </div>
        </div>
    )
}
```

따라서 사용자의 기기 성능이 좋지 않아도, 서버에서 정제된 데이터를 전송받으므로 빠른 속도를 경험합니다.

**동적 라우팅의 끝판왕 - Catch All Segments**

우리가 지금까지 배운 동적 라우팅인 \[id\] 방식은 단일 폴더인 경우만 적용되었습니다.

그러나 문제의 핵심은 같은 구조의 상세 페이지임에도 폴더 깊이가 달라 처리하기에 곤란합니다.

![](/images/posts/68/18.png)

이러한 무한히 깊어지는 계층 구조를 해결하기 위해 등장한 것이 **Catch-all Segments** 기술입니다.

Javascript에서 배열이나 객체의 나머지 요소를 한번에 가져올 때 사용하는 **스프레드 연산자**를 적용한 것입니다.

폴더 뒤에 오는 모든 하위 경로를 단 하나의 배열로 만드는 것입니다.

![](/images/posts/68/19.png)

이 개념을 실제 프로젝트에 적용하기 전에 **\[...slug\]** 방식과 **\[\[...slug\]\]** 방식의 차이도 이해해야 합니다.

첫번째 케이스인 대괄호 한 개만 감싸는 경우, 하위 경로가 반드시 하나 이상일 때 정상적으로 배열을 반환합니다.

그러나 하위 경로가 없을 경우에는 상위 폴더로 접근할 시 오류가 발생합니다.

두번째 케이스인 대괄호 2개로 감싸는 경우, 역시 하위 경로가 있을 때 정상적으로 배열을 반환합니다.

그리고 하위 경로가 없어도 빈 배열을 반환하여, 메인 페이지를 보여줍니다.

메인 페이지부터 하위 경로까지 파일을 하나로 통제하고 싶다면 **\[\[...slug\]\]** 방식을 이용할 것입니다.
