<img src="/media/images/uploads/1793750661634.png" width="636" data-align="left" style="display: block; height: auto; max-width: 100%; margin: 0px auto 0px 0px;"><h3><strong>백엔드 엔지니어란?</strong></h3><p>백엔드 엔지니어란 서버 사이드(Server Side) 프로그램을 디자인하고 개발, 유지보수하는 역할을 합니다.</p><p>백엔드는 REST API, GraphQL, gRPC 프로토콜 등을 통해 프론트엔드가 통신할 수 있는 영역입니다.</p><img src="/media/images/uploads/1793750831124.png" width="580" data-align="left" style="display: block; height: auto; max-width: 100%; margin: 0px auto 0px 0px;"><p>백엔드를 조금 더 세분화하여 얘기하자면, API Server / Database / Infrastructure로 구분됩니다.</p><p><strong>API Server</strong>는 프론트엔드와 백엔드 혹은 백엔드끼리의 연결을 가능하게 해주는 영역입니다.</p><p>즉, 프론트엔드에서 요청이 왔을 때 실제 비즈니스 로직을 수행하는 곳입니다.</p><p>관련된 키워드로는 Nest.js / Django / Spring / GraphQL / REST API / gRPC 등이 있습니다.</p><p><strong>Database</strong>는 데이터 저장소입니다. API Server에서 비즈니스 로직을 수행할 때 잊어버리는 안되는 정보들</p><p>예를 들어, 인스타그램에서 올린 Post의 제목, 내용, 이미지들, 좋아요 개수 등을 서버에서 기억해야 합니다.</p><p>API Server에서 Database에 전송을 한 다음에 Database에 입력을 해서 데이터가 사라지지 않도록</p><p>저장하는 공간입니다.</p><p>관련 키워드로는 Postgresql / MySQL / OracleDB / MongoDB / DynamoDB 등이 있습니다.</p><p><strong>Infrastructure</strong>는 백엔드를 실행하는 하드웨어를 관리하는 영역입니다.</p><p>Cloud Engineer 혹은 DevOps Engineer들이 이쪽에 속하는 엔지니어들입니다.</p><p>키워드는 Cloud, Kubernetics, DevOps 등이 있습니다.</p><img src="/media/images/uploads/1793751528745.png" width="654" data-align="left" style="display: block; height: auto; max-width: 100%; margin: 0px auto 0px 0px;"><h3>Node.js 소개</h3><p>Node.js란 오픈소스 / 크로스 플랫폼 / 자바스크립트 런타임 엔진입니다.</p><ul><li><p>오픈소스는 누구나 볼 수 있도록 소스 코드가 공개되어 있다는 의미입니다.</p></li><li><p>크로스 플랫폼은 여러 OS에서 사용할 수 있다는 의미입니다.</p></li><li><p>자바스크립트 런타임은 자바스크립트를 실행할 수 있다는 의미입니다.</p></li></ul><p>실제로, <a target="_blank" rel="noopener noreferrer nofollow" href="https://github.com/nodejs/node">https://github.com/nodejs/node</a> 에서 확인할 수 있습니다.</p><p>Node.js 즉 자바스크립트는 인터프리터 언어 중에 하나인데, 컴파일 언어와의 차이점을 이해할 필요가 있습니다.</p><ul><li><p>컴파일 언어 : 프로그램을 실행하기 전에 작성된 코드를 기계어로 한번에 변환한 후 실행합니다.</p></li><li><p>인터프리터 언어 : 프로그램을 실행하면서 동시에 코드를 한줄 한줄씩 변환하면서 실행합니다.</p></li></ul><p>그 중 V8 자바스크립트 엔진은 JIT 컴파일러를 사용합니다.</p><p>JIT (Just In Time) 컴파일러는 컴파일 방식과 인터프리터 방식의 장점을 모아둔 형태입니다.</p><p>과정은 다음과 같습니다.</p><ol><li><p>코드 실행 환경을 준비하고, 컴파일을 합니다.</p></li><li><p>바이트 코드로 생성 및 변환합니다.</p></li><li><p>Ignition 툴을 사용해 인터프리터 방식으로 실행합니다.</p></li><li><p>이 중 자주 쓰는 코드를 최적화하여 Turbofan 툴로 머신 코드로 변환하고 컴파일합니다.</p></li><li><p>최적화를 해놓은 코드가 변경이 되었다면, 최적화를 풀어 바이트 코드로 변환해 인터프리터 방식으로 바꿉니다.</p></li></ol><p>이번엔 Node.js의 싱글 스레드 모델에 대해 알아보겠습니다. </p><img src="/media/images/uploads/1793753457895.png" width="492" data-align="left" style="display: block; height: auto; max-width: 100%; margin: 0px auto 0px 0px;"><p>데이터베이스 요청이나 네트워크 요청이 오래 걸리지 않는 논 블로킹 요청을 받으면</p><p>이벤트 큐라는 곳에 쌓이고, 싱글 스레드인 이벤트 루프가 요청을 하나씩 pop 시킵니다.</p><p>논 블로킹의 요청의 경우 이벤트 루프에서 굉장히 빠르게 처리해서 다시 프론트엔드로 응답을 보냅니다.</p><p>반대로, 막힐 만한 블로킹 요청이 들어온다면, 마찬가지로 이 요청도 이벤트 큐라는 곳에 쌓이고</p><p>이벤트 루프가 하나씩 pop해 요청을 빼오지만 이벤트 루프가 직접 처리하려고 기다리고 있으면</p><p>이벤트 루프가 막혀 다른 이벤트 큐에 있는 작업을 못 가져올 것 같으므로</p><p>오른쪽에 워커 스레드라는 CPU의 여러 스레드를 보관하고 있는 곳의 남는 스레드 중 하나한테</p><p>블로킹 요청을 그냥 보내버립니다. 그러면, 이벤트 큐에 있는 요청을 다시 가져갈 수 있습니다.</p><p>만약 워커 스레드에서 요청이 끝났다면, 다시 블로킹 요청을 가져와 다시 프론트엔드에 보냅니다.</p><p>즉, 싱글 스레드인 이벤트 루프가 항상 막혀있지 않도록 유지하는 방식입니다.</p><h3>HTTP</h3><p>HTTP는 클라이언트와 서버가 통신하는 방법 중 하나로써 클라이언트가 요청을 보내면 서버가 응답을 반환합니다.</p><p>요청과 응답의 구조화된 데이터를 보낼 때는 일반적으로 JSON 구조를 사용합니다.</p><img src="/media/images/uploads/1793753728416.png" data-align="center" style="display: block; height: auto; max-width: 100%; margin: 0px auto;"><p>여기서 JSON 구조는 JS 객체 혹은 여타 언어의 Map 구조와 매우 비슷한 모습으로써</p><p>프론트엔드에서 보낼 때 String으로 변환하고 다시 받으면 JSON으로 변환합니다.</p><p>Key-Value 쌍으로 이루어지는 구조의 형태이며, Key 값은 String만 허용됩니다.</p><img src="/media/images/uploads/1793754064953.png" width="483" data-align="left" style="display: block; height: auto; max-width: 100%; margin: 0px auto 0px 0px;"><p>HTTP 요청의 구성요소를 자세히 살펴보자면, URL / Method / Header / Body로 구성됩니다.</p><img src="/media/images/uploads/1793754363826.png" data-align="left" style="display: block; height: auto; max-width: 100%; margin: 0px auto 0px 0px;"><p>URL은 요청을 보낼 주소로써 다음과 같은 구조로 형성됩니다.</p><img src="/media/images/uploads/1793754710992.png" width="550" data-align="left" style="display: block; height: auto; max-width: 100%; margin: 0px auto 0px 0px;"><ul><li><p>항상 앞에 붙는 http 혹은 https를 스킴(Scheme)이라고 합니다.</p></li><li><p>그 다음 흔히 도메인이라고 부르는 영역을 호스트(Host)라고 합니다.</p></li><li><p>그 다음 / 하고 오는 부분을 패스(Path)라고 합니다. 도메인에서 요청하는 리소스를 의미합니다.</p></li><li><p>그 다음 ? 하고 오는 부분을 쿼리파라미터(Query Parameter)입니다. 요청하는 추가 정보입니다.</p></li></ul><p>Method는 요청 방법으로 GET / POST / PUT / PATCH / DELETE가 있습니다.</p><ul><li><p>GET은 데이터를 읽을 때 사용합니다.</p></li><li><p>POST는 데이터를 생성할 때 사용합니다.</p></li><li><p>PUT은 데이터를 업데이트하거나, 없을 경우 생성할 때 사용합니다.</p></li><li><p>PATCH는 데이터를 업데이트할 때만 사용합니다.</p></li><li><p>DELETE는 데이터를 삭제할 때 사용합니다.</p></li></ul><p>Header는 요청의 메타데이터로 우리가 보내는 HTTP 요청에 대한 정보를 Header에 넣습니다.</p><p>Body는 실제 요청에 관한 본문 데이터를 의미합니다.</p><p>다음으로, HTTP 응답의 구성요소를 살펴보면, Status Code / Header / Body로 구성됩니다.</p><img src="/media/images/uploads/1793755264798.png" data-align="left" style="display: block; height: auto; max-width: 100%; margin: 0px auto 0px 0px;"><p>Status Code는 응답의 상태에 따라 숫자를 변경해서 보내게 됩니다.</p><p>100부터 599까지의 숫자를 사용합니다.</p><ul><li><p>100 ~ 199 : 정보 응답</p></li><li><p>200 ~ 299 : 성공 응답</p></li><li><p>300 ~ 399 : 리다이렉션 메시지</p></li><li><p>400 ~ 499 : 클라이언트 에러 응답</p></li><li><p>500 ~ 599 : 서버 에러 응답</p></li></ul><p></p>
