# 검토 점검표

arch-reviewer 와 finding-verifier 가 씁니다. 각 항목은 "어기면 무엇이 깨지는지"와 함께 적었습니다. 지적할 때는 그 실패 시나리오를 구체적인 입력 · 상태로 적습니다.

## 아키텍처

| # | 점검 | 어기면 |
|---|---|---|
| A1 | `params` · `searchParams` · `cookies()` · `headers()` 를 읽는 컴포넌트가 `<Suspense>` 안인가 | build 의 prerender 실패 |
| A2 | prerender 되는 경로에 `Date.now()` · `new Date()` (인자 없이 현재 시각) 가 없는가 → `nowMs()` | build 실패 또는 불안정한 값 오류 |
| A3 | 공개 화면용 새 읽기 함수에 `"use cache"` + `cacheTag(TAGS.*)` + `cacheLife(LIFE.*)` 가 있는가. 태그 · 수명을 문자열로 직접 쓰지 않았는가 | 캐시가 안 되거나, 무효화 태그와 이름이 어긋남 |
| A4 | 데이터를 바꾸는 Server Action 이 영향받는 모든 태그를 `updateTag` 하는가 (글 → `TAGS.posts`, 댓글 → `TAGS.comments(slug)`, 방명록 → `TAGS.guestbook`) | 공개 화면이 수명 동안 옛 내용 |
| A5 | 관리자 액션 첫 부분에 `await requireAdmin()` 이 있는가 | 허용 IP · 계정이 아닌 사람이 POST 로 실행 |
| A6 | 클라이언트 컴포넌트(`"use client"`)나 클라이언트에서 import 되는 모듈이 `@/lib/db` · `server-only` 모듈을 끌어오지 않는가 | build 실패 |
| A7 | 공개 조회가 `draft: true` 글을 빼는가 | 임시 글 노출 |
| A8 | 관리자 화면 읽기는 캐시 없는 `load*` 를 쓰는가 | 저장 직후 관리자 화면에 옛 값 |
| A9 | 홈(`/`) 링크가 `next/link` 인가 (`<a href="/">`, `location.href = "/"` 아님) | 인트로로 튕김 |
| A10 | `html` 상태 전환을 `:has()` 로 하지 않았는가 | 다른 화면까지 잠기거나 테마가 샘 |
| A11 | 새 화면이 맞는 그룹에 있는가 (`(site)` / `intro` / `(studio)`), `not-found` 흐름을 깨지 않는가 | 헤더 · 푸터 중복 또는 누락 |
| A12 | 에디터 폼 필드 이름이 `savePost` 가 읽는 이름과 같은가, Enter 로 제출되지 않는가 | 저장 값 누락, 실수로 발행 |
| A13 | `/admin` 이하 새 경로가 `src/proxy.ts` 의 IP 검사 범위에 들어가는가 | 관리자 화면 노출 |
| A14 | `.post-body` 를 바꿨다면 공개 글 · 미리보기 · 에디터 세 곳 모두에서 맞는가 | 화면마다 본문이 다르게 보임 |
| A15 | 사용자 입력(slug, 카테고리 경로, 댓글)을 검증하는가, 업로드는 4MB 제한을 지키는가 | 잘못된 데이터 저장, 413 |

## 정확성 (일반)

- 비동기 결과를 `await` 하지 않음, 오류를 삼켜 화면이 빈 채로 성공처럼 보임.
- 페이지네이션 · 검색(`?page`, `?q`)이 서로를 지우지 않는가 (검색 중 페이지 이동 시 검색어 유지).
- 바꾼 함수의 다른 호출처가 새 시그니처와 맞는가.

## 지적하지 않는 것

- 포매팅, 이름 취향, "이렇게 하면 더 깔끔" 류 — 이 하네스의 검토 목적은 깨지는 것을 찾는 것입니다.
- CLAUDE.md · `docs/*` 에 예외로 적힌 것: 관리자 `load*` 무캐시, 인트로 · 에디터 자체 토큰, 로고 고정색, `featured` 를 공개 화면이 안 쓰는 것.
